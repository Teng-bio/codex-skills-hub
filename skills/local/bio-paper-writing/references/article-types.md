# Bioinformatics Article Types

Choose the closest architecture before drafting. If the paper mixes types, use the dominant claim as the spine.

## Omics discovery paper

Common evidence: differential expression, clustering, pathway enrichment, regulatory or phenotype associations.

Default logic:

1. biological context and unresolved question
2. dataset and analysis strategy
3. major molecular pattern
4. pathway/cell-type/module interpretation
5. validation or external support
6. implication and boundary

## Resource, atlas, or database paper

Common evidence: dataset scale, annotation quality, coverage, accessibility, reuse cases.

Default logic:

1. community need
2. resource construction and quality control
3. content and scale
4. benchmark or validation
5. use cases
6. reuse limits and availability

## Computational method or pipeline paper

Common evidence: algorithm design, benchmark datasets, baseline comparisons, ablation, runtime, usability.

Default logic:

1. technical bottleneck
2. method idea
3. fair benchmark design
4. performance against baselines
5. robustness, ablation, or sensitivity
6. availability and use cases

## Biomarker or clinical-translational paper

Common evidence: cohorts, model performance, external validation, calibration, confounder control.

Default logic:

1. clinical or translational need
2. cohort/data design
3. discovery signal
4. model or marker performance
5. external validation and bias assessment
6. clinical boundary and future validation

## Mechanism-oriented bioinformatics paper

Common evidence: computational association plus experimental or external database support.

Default logic:

1. mechanism gap
2. computational screen or multi-omics integration
3. candidate pathway/gene/module
4. orthogonal support
5. functional interpretation
6. causal boundary and validation needs
